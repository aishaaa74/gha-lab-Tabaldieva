 1- Workflow состоит из jobs, а каждый job состоит из steps. Steps выполняют определённые команды или действия. То есть структура такая: workflow → jobs → steps.
 2- Job — это отдельная задача, которая выполняется на виртуальной машине. Step — это отдельный шаг внутри job. Например, job может состоять из нескольких steps: скачать проект, установить зависимости и запустить тесты.
 3- При push workflow запускается автоматически, когда мы отправляем изменения в репозиторий. А workflow_dispatch позволяет запускать workflow вручную через кнопку в GitHub Actions.
 4- Для этого используются GitHub Secrets. Мы сохраняем пароль или токен в настройках репозитория, а потом обращаемся к нему в workflow через ${{ secrets.NAME }}. Так не нужно записывать пароль прямо в код
 5- Артефакт — это файл, который создаётся во время выполнения workflow и который можно сохранить, скачать или передать между jobs. Например, в нашей работе первый job создаёт файл report.txt, загружает его, а второй job скачивает и показывает его содержимое
 6- Чтобы один job дождался другого, используется needs. Например, needs: build означает, что job show начнётся только после завершения job build
